# Модели бизнес-процессов модерации контента

## 1. Процесс "AS-IS" (До внедрения автоматической модерации)

До внедрения интеллектуальной системы фильтрации модерация 500 000 комментариев ежедневно носит выборочный, ручной и хаотичный характер.

### Графическое описание процесса (IDEF0 / BPMN)

В текущем процессе ("как есть") входящий поток комментариев сохраняется непосредственно в общую транзакционную базу данных. Затем дежурные модераторы осуществляют периодические случайные выборки комментариев через административный веб-интерфейс, пытаясь обнаружить нежелательный или незаконный контент.

### Проблемы процесса AS-IS:
- Пропуск опасного контента: Более 80% токсичных комментариев не проверяются вообще, попадая в категорию "без проверки".
- Угроза санкций РКН: Скорость удаления токсичных или запрещенных комментариев составляет от 4 до 24 часов, при этом требования регулятора предписывают оперативное скрытие такого рода контента. Возникает повышенный риск штрафов.
- Высокая стоимость: Раздутый штат ручной фильтрации, модераторы утомляются и допускают субъективные ошибки.

## 2. Процесс "TO-BE" (После интеграции ИИ-сервиса модерации)

Интеграция ИИ автоматизирует проверку 100% входящих комментариев в реальном времени, делегируя человеку управление исключительно пограничными (низкоуверенными) прецедентами.

### Схема функциональной декомпозиции (IDEF0 A1)

Ниже представлена детальная функциональная структура новой системы модерации в соответствии с методологией IDEF0 (подуровень A1).

![IDEF0 A1](https://raw.githubusercontent.com/lk2322/ml-system-design-sentiment/docs-diagrams-setup/docs/assets/diagrams/idef0_a1.svg)

- Вход (Input): Поток сырых необработанных комментариев из социальных сетей.
- Управление (Control): Нормативные требования РКН, внутреннее ограничение SLA (время инференса < 200 ms), политики конфиденциальности (ФЗ-152) и выделенный аппаратный лимит.
- Механизмы (Mechanism): Микросервис на базе Triton Inference Server с GPU, брокер Kafka, квалифицированные модераторы и подсистема Active Learning.
- Выход (Output): Размеченная и оперативно отфильтрованная база, логи аудита и проверенные инкременты данных для переобучения.

### Процесс управления очередями модерации (BPMN TO-BE)

Процесс "как будет" детально описывает потоки управления, разделенные по пулам и дорожкам между пользователями, API Gateway, микросервисом инференса ML и ручными модераторами:

![BPMN TO-BE](https://raw.githubusercontent.com/lk2322/ml-system-design-sentiment/docs-diagrams-setup/docs/assets/diagrams/bpmn_to_be.svg)

1. Комментарий отправляется пользователем и немедленно попадает в асинхронную очередь брокера событий (Kafka raw_comments). Пользователь сразу получает HTTP 202.
2. Легковесный ML-воркер (RuBERT) вычисляет степень токсичности (Toxicity Score) и тональность (Sentiment) сообщения.
3. Разделение по порогу уверенности (Confidence Score):
   - Высокая уверенность (> 85%) + Токсично: Автоматическое превентивное скрытие комментария на платформе (время реакции < 1 секунды).
   - Высокая уверенность (> 85%) + Безопасно: Одобрение и публикация комментария в публичном доступе.
   - Низкая уверенность (< 85%): Перенаправление спорного комментария во внутреннюю очередь (Moderator Task Queue) на ручную проверку.
4. Модераторы разбирают спорные комментарии на веб-панели. Их вердикт (Approve/Reject) сохраняется, а сам прецедент вместе с текстом записывается в базу Active Learning для последующего еженедельного дообучения RuBERT.

### Что меняет разрабатываемая система:
- Охват проверки: Увеличен с выборочных 15% до полных 100% входящего потока.
- Время реакции на жесткий негатив/спам: Упало с нескольких часов до 200 миллисекунд (автофильтр).
- Нагрузка на персонал: Снижена более чем на 75%. Модераторы не читают очевидный нейтральный поток (составляющий 80-90% объема), а фокусируются на сложных, завуалированных или спорных сообщениях.
- Защита от санкций регуляторов (РКН): Гарантированное удаление запрещенных материалов за считанные секунды со 100% надежностью благодаря ИИ и приоритизированной ручной эскалации.

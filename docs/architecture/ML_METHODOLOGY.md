# ML-методология и мониторинг

## 1. Данные и сущности

| Название данных | Источник | Роли | Качество |
| ------------- | ------------- | ------------- | ------------- |
| Комментарии | Sharded PostgreSQL | DE/DA | Проверено |
| Разметка токсичности | Внутренняя БД модерации | DS/Moderators | Требует валидации |
| Открытые датасеты | OK Toxic, Kaggle | DS | Высокое |

## 2. Выбор модели и алгоритмов

Для анализа тональности и выявления неприемлемого контента на русском языке выбраны следующие подходы:

- **Базовая модель:** RuBERT (Russian BERT) от DeepPavlov или sberbank-ai.
- **Задача:** Мультиклассовая классификация (Positive, Neutral, Negative, Toxic, Insult, Threat).
- **Обучение:** Fine-tuning предобученного трансформера на специфичном домене (соцсети, комментарии).

## 2. Пайплайн обучения (Training Pipeline)

1. **Сбор данных:** Использование открытых датасетов (OK Toxic, Kaggle Sentiment) + внутренняя разметка модераторов.
2. **Препроцессинг:** Очистка от спецсимволов, нормализация эмодзи, токенизация (WordPiece).
3. **Валидация:** Cross-validation, оценка на отложенной выборке (Hold-out set).
4. **Эксперименты:** Отслеживание в MLflow (параметры, метрики, артефакты).

## 3. Мониторинг и поддержка

### 3.1. Технический мониторинг (Infrastructure)
- **Latency:** Время инференса модели (цель < 200ms).
- **Throughput:** Количество обработанных комментариев в секунду.
- **Error Rate:** Процент падений сервиса инференса.

### 3.2. ML-мониторинг (Model Health)
- **Data Drift:** Изменение распределения входных текстов (новые сленговые слова, темы).
- **Prediction Drift:** Сдвиг в распределении предсказанных классов.
- **Online Evaluation:** Регулярная проверка случайных предсказаний модели модераторами для расчета "живого" Precision/Recall.

### 3.3. Переобучение (Retraining)
- Автоматический запуск переобучения при падении точности ниже порога (например, F1 < 0.8).
- Еженедельное дообучение на новых данных, размеченных модераторами (Active Learning).

# Архитектурное проектирование системы

## 1. Схема распределенной архитектуры инфраструктуры

Система спроектирована по микросервисной схеме с использованием событийно-ориентированной интеграции (EDA) на базе Apache Kafka и оркестрации контейнеров в Kubernetes cluster.

### Карта архитектуры распределенной системы

![Карта распределенной архитектуры](https://raw.githubusercontent.com/lk2322/ml-system-design-sentiment/docs-diagrams-setup/docs/assets/diagrams/system_architecture.svg)

Схема наглядно иллюстрирует движение потоков информации и точки интеграции компонентов:
1. **API Ingestion Service:** Принимает входящие REST API запросы на публикацию комментариев со стороны веб-клиентов и мобильных приложений.
2. **Брокер сообщений (Apache Kafka):** Действует как буфер сглаживания сетевых пиков нагрузки. Входящие комментарии транслируются в топик `raw_comments`.
3. **ML Sentiment Worker:** Легковесный консьюмер на Python (asyncio), забирающий пачки комментариев из Kafka. Он осуществляет предобработку, взаимодействует с сервером инференса и публикует предсказания тональности/токсичности.
4. **Triton Inference Server:** Специализированное высокопроизводительное решение от NVIDIA для оптимизированного инференса NLP-модели (RuBERT) на GPU с поддержкой динамического батчинга (Dynamic Batching) и параллельного инференса.
5. **Система распределенного хранения:** Шардированный кластер PostgreSQL для транзакционного хранения контента, колоночная СУБД ClickHouse для логов модерации и аналитики, Elasticsearch для полнотекстового поиска по истории.
6. **Compliance & Manual Moderation Portal:** Дашборд администраторов модерации и модераторов-людей, позволяющий обрабатывать эскалированные (низкоуверенные) задачи разметки в реальном времени.

## 2. UML-диаграмма компонентов и классов системы

Для точного объектно-ориентированного и модульного описания системы на уровне кода и пакетов разработана UML-диаграмма, объединяющая схему компонентов и классов модулей ML‑пайплайна.

### Модель компонентов и классов

![UML Диаграмма компонентов и классов](https://raw.githubusercontent.com/lk2322/ml-system-design-sentiment/docs-diagrams-setup/docs/assets/diagrams/uml_components.svg)

### Описание структуры компонентов:
- `IngestionService` — Предоставляет HTTP интерфейс, отвечает за первичную валидацию тела запроса и проверку JWT-авторизации пользователя перед публикацией сообщения.
- `MLInferenceWorker` — Реализует паттерн «Потребитель сообщений» (Message Consumer). Обеспечивает токенизацию текстов с помощью WordPiece-токенизатора и делает gRPC-запросы к инференс-движку Triton.
- `DataStorageManager` — Абстракция для сокрытия работы с разнородными СУБД, предоставляющая единые репозитории взаимодействия с PostgreSQL, Elasticsearch и ClickHouse.
- `ModerationDashboard` — Веб-составляющая (React/NextJS) и асинхронный сервер очередей (FastAPI + Celery), координирующие распределение пограничных задач модераторам-людям.

### Описание ключевых классов:
- `CommentIngestor` — Управляет входящими пакетами, проверяет ограничения по длине текста и спам-лимитам, публикует события в шину Kafka.
- `ClassifierEngine` — Инкапсулирует работу с весами RuBERT модели. Отправляет батчи токенизированного текста в GPU-инференс, возвращая структурированные вероятности классов.
- `ModerationActionManager` — Координатор бизнес-логики принятия решений. На основе полученных от `ClassifierEngine` оценок и порогов уверенности вызывает автоматическое скрытие контента, направляет задачу на эскалацию ручной проверки или отправляет финальный лог в ClickHouse.

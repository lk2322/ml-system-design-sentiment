# Поведенческое проектирование системы

## 1. Схема динамических процессов (UML Activity Diagram)

Диаграмма активностей (Activity Diagram) формализует логику ветвления алгоритмов обработки контента в зависимости от уверенности (Confidence Ratio) моделей искусственного интеллекта. Она отражает сквозные сценарии реагирования — от момента написания сообщения пользователем до финального логирования и отправки данных для повторного обучения (Active Learning Loop).

## 2. Схема последовательности взаимодействия (UML Sequence Diagram)

Диаграмма последовательности (Sequence Diagram) иллюстрирует временную шкалу и порядок вызовов методов, сообщений и gRPC/REST запросов между распределенными компонентами ИИ-решения при асинхронном выполнении модерации в реальном времени.

### Основные сценарии взаимодействия:

1. **Сценарий авто-модерации с высокой уверенностью (Положительный / Отрицательный контент):**
   - Клиент отправляет комментарий на шлюз `API Gateway`.
   - Шлюз мгновенно возвращает статус `202 Accepted` клиенту, отправляя комментарий в брокер `Kafka` для асинхронной обработки.
   - Свободный воркер `ML Sentiment Worker` вычитывает событие, подготавливает внутренний батч и передает его в `Triton Inference Server` для быстрого выполнения инференса на GPU.
   - Получив высокий балл токсичности при высоком пороге уверенности модели (> 0.85), воркер моментально обновляет статус комментария в `PostgreSQL` на `hidden`, посылая сигнал шлюзу `API Gateway` для скрытия сообщения на веб-фронтенде.
   - Запись о превентивном скрытии и логи модерации отправляются в аналитическое хранилище `ClickHouse`.

2. **Сценарий эскалации при низкой уверенности ML-модели:**
   - Если модель выдает спорные пограничные результаты (например, уверенность классификатора составляет 55%), `ML Sentiment Worker` сохраняет промежуточный статус комментария как `pending`.
   - Задача автоматически направляется на дорожку эскалации — регистрируется в базе очередей ручной обработки и отображается на рабочей веб-панели модераторов.
   - Свободный модератор принимает решение по комментарию (Approve / Reject).
   - Результат ручного решения обновляет статус контента в базе данных и отправляется по шине с пометкой обратной связи (Feedback loop), попадая в базу Active Learning для переобучения модели.
